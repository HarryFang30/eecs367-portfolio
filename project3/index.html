The robot

A robot made of boxes, cylinders and spheres

p3_dancer is a robot I wrote for this project. It is about 1.2 m tall and uses only primitive visuals with URDF material colours, so any viewer can draw it without mesh files. It rolls on a wheeled base, lifts its torso, turns at the waist, and has a head with an antenna and two arms (shoulder, elbow, wrist) that end in two-finger grippers.

I also designed it to exercise the parts of the URDF spec that are easy to get wrong:

  • Root is not firstbase_link is the root but not the first <link> in the file, so the root has to come from the joints.
  • Non-unit revolute axisThe head-pan axis is written 0 0 2 and must be normalized before it is used as a rotation axis.
  • Non-unit prismatic axisThe fingers slide along ±0.25 0 0, deliberately not unit: a prismatic joint moves q · axis exactly as written.
  • Tilted originsThe wheels get their tilt from an rpy origin, and the continuous waist can turn a full 2π.

The choreography

dancer_routine: 15 states, one loop in about 19 s

The choreography is a finite state machine. Each state is a joint-space setpoint for all 19 movable joints, and each state names the transition to take when the robot arrives. The last state leads back to home, so the dance loops.

Enter a stateThe FSM publishes its setpoint on /joint_trajectory.
Arrive/joint_states shows every joint within ε = 0.03 of the setpoint.
Hold, then move onAfter the state's hold time, fire its on_arrival transition.

How it runs

Five nodes on my Project 1 middleware

The runtime is written in Python on top of the publish/subscribe hub and rosbridge-style TCP/JSON gateway I built in Project 1. make demo starts five nodes in one process, and they talk only through the hub, the same way they would over a network.

finite_state_machine

Loads the choreography from fsm/dancer_routine.json and publishes each state's setpoint.

joint_state_publisher

Moves every joint toward its setpoint with a proportional servo (velocity = gain × error, capped, never overshooting, clamped to the joint limits) and publishes /joint_states.

robot_state_publisher

One transform per joint, T = Torigin(xyz, rpy) · Tmotion(q), on /tf. Revolute and continuous joints rotate about the normalized axis; prismatic joints slide along the axis as written.

robot_world_state_publisher

Walks the tree from the root, composes Tworld,child = Tworld,parent · Tjoint, and publishes every link's 4×4 pose on /xform_world as 16 column-major numbers.

The URDF parser, the quaternion and 4×4 matrix math, and the tree traversal are all my own code. As the project requires, no kinematics, transform or URDF-model library is used; the only borrowed piece is Python's standard-library XML parser.

How I drew it

A viewer that trusts the runtime's matrices

The course supplies no viewer, so I built one as an external client of the runtime. A browser cannot open a raw TCP socket, so a small bridge, viewer_server.py (Python standard library only), connects to the gateway on port 9095 like any other rosbridge client. It subscribes to /xform_world, /tf, /joint_states, /global_pose and /fsm/status, and streams them to the page with server-sent events.

The page uses three.js. Each link is a THREE.Group with matrixAutoUpdate = false, and every /xform_world message is copied straight in. The viewer never corrects a matrix, so any FK mistake would show up on screen.

// scene.js: pose every link from one /xform_world message
for (const entry of message.transforms) {
  const view = this.links.get(entry.child_frame_id);
  view.group.matrix.fromArray(entry.matrix);   // column-major, exactly as published
}

Drawing each link

Inside each group the link's first <visual> is drawn at its visual origin with its URDF colour. Boxes and spheres are drawn as written. Cylinders are turned 90° about x, because three.js cylinders run along +y and URDF cylinders along +z. The camera is z-up to match URDF.

Recording the video

  1. Start the runtime with the servo and FSM nodes: make demo.
  2. Load the robot and deploy the choreography with my script, tools/demo.py.
  3. Record the 3D canvas with the viewer's Record button (canvas.captureStream and MediaRecorder), then add the caption with ffmpeg.

The viewer also has an independent FK self-check, a slider per joint and FSM controls, which I used while debugging.
